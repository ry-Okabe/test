クライアント証明書 配布形式 検証 iOS実機用

端末認証用のクライアント証明書を、P12形式とモバイルコンフィグ形式（.mobileconfig）で配布し、iPadでのインストールUXの差を比較する検証ページです。（内部定例 2026/11/10 の技術検証タスク①）
検証用CA＝COTA Device Root CA／クライアント証明書＝CN=salon-00123-ipad-01（clientAuth）。P12パスワード＝ cota1234。※これは検証専用の自己署名CAです。本番は別CA・別鍵で発行します。

① モバイルコンフィグ形式（.mobileconfig）＝タップで完結（本命）

.mobileconfig をダウンロード

P12を内包した構成プロファイル。Safariでタップ→「プロファイルがダウンロードされました」→設定アプリでインストールだけで、証明書（鍵+証明書）がキーチェーンに入ります。パスワードはプロファイルに埋め込み済み＝手入力ほぼ不要。

  1. Safari でこのボタンをタップ
  2. 「このWebサイトは構成プロファイルをダウンロードしようとしています」→ 許可
  3. 「プロファイルがダウンロードされました」表示
  4. 設定アプリ → 一番上の「プロファイルがダウンロード済み」→ インストール（パスコード入力）→ 完了

② P12形式（.p12）＝手動手順が多い（比較用）

client.p12 をダウンロード

PKCS#12（鍵+証明書）。iOSではダウンロード→設定アプリでプロファイルとしてインストール→P12パスワード cota1234 を手入力が必要。ファイルアプリ経由だと手数が増えます。

  1. Safari でこのボタンをタップ → ダウンロード
  2. 設定アプリ → 「プロファイルがダウンロード済み」→ インストール
  3. 証明書のパスワード cota1234 を手入力 → 完了
  4. （ファイルアプリに落ちた場合）ファイルApp → 当該.p12をタップ → 設定に誘導 → 同上

③ CA証明書（任意・サーバmTLS検証用）

ca.crt（ルートCA）をダウンロード

サーバ側でmTLSのクライアント検証に使うCA。端末側の信頼設定の確認にも。

確認ポイント（実機で見る）

観点.mobileconfigP12
インストール操作タップ→設定で数タップダウンロード→設定→パスワード手入力
パスワード入力不要（埋め込み）必要（cota1234）
ファイルApp経由の手間ほぼ無し発生しやすい
インストール後の確認設定 → 一般 → VPNとデバイス管理 → プロファイルに「COTA 端末証明書プロファイル」/証明書が表示されるか

※ インストール後、キーチェーンに入ったクライアント証明書が PWA/アプリ内ブラウザから mTLS で提示されるかは別途サーバ検証が必要（Safari単体は提示可、PWA/WKWebViewは要確認）。この点が「証明書で端末束縛」する際の最重要チェックです。

発行の実装方針（検証の目的）：本番は 新システム側で発行（自前プライベートCA or クラウド） し、キッティング時にWebで配布（.mobileconfig動的生成）。失効・更新は端末マスタ[Device]で管理。
