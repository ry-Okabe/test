# mTLS 保護サーバ（証明書がないとアクセスできない遷移先）

GitHub Pages は mTLS（クライアント証明書認証）を強制できないため、**保護ページはこのローカルサーバで実現**します。
`Test Device Root CA` で署名されたクライアント証明書を持つ端末だけがアクセスでき、無い端末は **403** になります。

## 前提
- Node.js（確認済み v24 でOK）
- `cert_test/` に `ca.crt` と `ca.key`（CA秘密鍵）があること（＝発行元。この端末のローカルにあります）
- iPad と PC が **同一 Wi‑Fi**

## 手順
1. **このPCのLAN IPを調べる**（例 `192.168.1.23`）
   - Windows: `ipconfig` の IPv4 アドレス
2. **サーバ証明書を生成**（`mtls_server/` 内で）
   ```sh
   sh gen_server_cert.sh 192.168.1.23
   ```
3. **サーバ起動**
   ```sh
   node server.js
   ```
   → `https://0.0.0.0:8443/` で待受
4. **iPad 側の準備**（Safari）
   - 検証サイトの `cert_test/` ページから
     - **ca.crt** をインストール＋**信頼を有効化**（設定→一般→情報→証明書信頼設定でルートCAをON）※サーバのTLSを信頼させるため
     - **クライアント証明書**（.mobileconfig か P12）をインストール
5. **iPad の Safari で `https://192.168.1.23:8443/` を開く**
   - クライアント証明書の使用可否を聞かれたら許可
   - **✅ アクセス許可（CN=test-device-01 表示）** が出ればmTLS成功
   - 証明書を入れていない端末／別端末では **⛔ 403** になる＝「証明書がないと入れない」実証

## PWA から開いた場合（最重要チェック）
- **ホーム画面に追加した PWA（standalone）/ アプリ内ブラウザから `https://<IP>:8443/` を開いて、クライアント証明書が提示されるか**を必ず確認。
  - Safari 単体では提示される一方、**PWA/WKWebView では提示されない**ことがあり、これが「証明書で端末束縛」できるかの分かれ目。
  - 提示されない場合は、App Check / 端末束縛トークン等の代替方式を検討（内部定例の持ち越し論点）。

## メモ
- `server.js` は `rejectUnauthorized:false` で手動判定し、分かりやすい 403 ページを返します。
  TLS 段階で完全に遮断したい場合は `rejectUnauthorized:true` に変更（ブラウザは接続エラー表示になります）。
- `server.crt/server.key`（サーバ証明書）とCA秘密鍵は**公開リポジトリに置かないこと**。
